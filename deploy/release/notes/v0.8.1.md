A small fix release that every node should take: four places that cut, slice or size things from input now hold for any input. Nothing else changes: it is 0.8.0 plus these fixes.

## Security

We recommend 0.8.1 for every node, resolver pods included. A security advisory with the details and the workarounds for earlier releases follows once this release is out and verified.

## Fixes

- **A name's sample keeps whole characters.** The anomaly engine keeps up to five sample names per device and minute; a sample is now cut at a character boundary, whatever bytes a name holds. Names that are plain ASCII are cut exactly as before.
- **A list compiles the same on any number of threads.** A large list split across three or more threads is cut at line ends however long its lines are, and the compiled filter is the same as on one thread. (A list of a few MiB with one very long line used to be cut past its end.)
- **A peer's reads are answered inside the API's own bounds.** The heatmap reads and the query-log read that one cluster node asks of another are answered within the windows and the page size the API itself uses. Requests the API sends are answered exactly as before.
- **A backup refuses a file its archive format cannot hold,** with an error that names the file, instead of writing a wrong size.

## Upgrading from 0.8.0

- Nothing to change: no configuration key, no wire format and no stored data changed. Upgrade replicas and resolver pods first, then the primary, as for any release. A node still on 0.8.0 keeps the behaviour above until it is upgraded, so take every node.
- The compiled filter and the compile statistics are the same as 0.8.0's.

## Known issues

Unchanged from 0.8.0: see its notes.
