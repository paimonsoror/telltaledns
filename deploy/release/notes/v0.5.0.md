A release for seeing your network over time and from new angles, and the release that passes the v1.0 gate's performance, memory, and security checks.

## Highlights

- **When things happen.** **Monitor → Heatmap** shows the network's queries (or blocked queries) by day and hour, 15 minutes, or minute, or a typical week; open it for one device or one name too. Select a cell for the query log at that time.

- **Where queries go.** **Monitor → Flow** draws every answer from group to decision (cached, forwarded, blocked, local) to upstream to response code. Every band is an exact count, never an estimate; SERVFAIL bands are red. For the whole network or one device, with **Live** refreshing it every 15 seconds.

- **Who spent the error budget?** Under each service-level objective, the bad answers broken down by device, name, upstream, status, response code, and node, with the budget left drawn over time.

- **Answer times as a heatmap.** The dashboard's **Where time goes** card (and each upstream's page) shows answers over time in latency bands, with the latency objective's threshold as a line. Its dots are real queries: select one to open it in the query log.

- **Every change on every chart.** Time charts draw a thin line for each configuration change (who made it, from where, which sections), restart, list refresh, rollout, maintenance window, pause, cache flush, and upstream breaker change. Operators and agents can add notes.

- **The odd node out.** **Cluster → Compare** puts every node side by side (queries per second, SERVFAIL, slow answers, cache, upstream failures, p50, p99) and outlines a node that really deviates, with a note when one only looks worse because it has little traffic.

- **A device's rhythm and day.** On the Clients page, **Rhythm** shows how regularly a device asks for each domain (a time-sync loop every 2.5 s is one dark cell), and **Day** shows its domains as swimlanes over 6 hours to 7 days, with blocked bursts, slow answers, first contacts, findings, and changes of identity marked. A device asking one domain faster than every 30 seconds for an hour is reported as a **chatty loop**, for your information only.

- **A wall display.** `#/wall` is a full-screen page for a monitor or tablet: the traffic map, the flow, the service level, answer times, and the week, rotating or all at once depending on the screen, with live queries along the bottom. An admin can make a **wall display** link for a screen nobody sits at: it stays signed in, can only show the wall, and can be limited to the screen's address.

- **A list that suddenly shrinks waits.** When a list download arrives with less than half the lines it had (`[filter] max_shrink_percent`, default 50), the previous copy keeps blocking until the next refresh brings the same content; **Refresh now** accepts it at once.

- **Measured for v1.0.** The shipped build idles at 13.7 MiB and holds a million blocked names with 100,000 cached answers in 60 MiB. On a Raspberry Pi 4, a recompiled 2-million-name filter answers 4.7 s after the change. With the load sent from another machine, 99.999 % of cached and blocked answers left the server within 250 µs.

- **Verifiable builds.** Release binaries carry their dependency list (`cargo auditable`), each comes with a CycloneDX SBOM, container images are signed with cosign (keyless), and two builds of the same commit are identical.

- **Also new:** the dashboard's controls (time range, Showing, Top lists, Changes) and every switch and drop-down across the site follow one style; view toggles are switches and view filters are pill drop-downs.

## Fixes

- **Security review (v1.0 gate).** Seventeen findings fixed, in sign-in, the cluster channel, and the parsers; see `docs/security-review.md`. The two rated high were both in the cluster: a resolver pod that left and came back with its still-valid certificate could be trusted with the cluster key, and an RPC answer from any member could answer a call made to another. Also: a query name with an escaped dot in a label got past the lists.
- **Zone transfers** (AXFR, IXFR) are refused instead of forwarded upstream.
- **An expired SERVFAIL is never served stale.**
- **Cluster page:** a node doing under 1 query per second showed 0 q/s, and resolver pods showed a 0 % cache hit rate (refreshed answers counted as misses). Both now match the dashboard.
- **Helm alerts covered only the controller.** With `prometheusRule.enabled` in scaled mode, the alerts and SLO rules now also watch the resolver pods, which answer most queries.
- **Quieter logs:** resolver pods no longer log an error for OIDC and a warning for router integrations they deliberately don't have the secrets for; a replica no longer repeats its file's warnings, or the "shared settings ignored" warning, on every change from the primary.

## Upgrading from 0.4

Most installs need no change. Check these if they apply to you:

- **Upgrading a cluster: check the registry first.** Nodes now trust only members the cluster's registry lists. Before upgrading, check (read-only) that `telltale cluster status` on the primary, or the Cluster page, lists every node; one missing would come back as a plain ephemeral member (not eligible to be primary). Then upgrade replicas first, then the primary: a 0.4 node refuses a configuration that uses a new setting, keeps the one it had, and logs `upgrade this node`.
- **Scripts that manage an account with a token:** changing a password or two-factor sign-in, and creating or deleting API tokens, now need a signed-in session (`POST /api/v1/auth/login`, then the cookie and `X-CSRF-Token`). An API token, an agent token, or HTTP Basic gets `403`. Revoking a wall display still works with an admin token.
- **Resolver pods** no longer receive users and token hashes; they serve no API, so nothing users do changes.
- **API and metrics:** `qps` on cluster nodes (`GET /api/v1/cluster`) is now a decimal (two places) instead of a whole number, and so is `telltale_cluster_peer_queries_per_second`. `telltale_cluster_peer_cache_hit_ratio` now counts refreshed and stale answers as hits.
- **Helm chart, alerts:** if you use `prometheusRule.enabled` in scaled mode, alerts can now fire for resolver pods too. With kube-prometheus-stack, give the rules its `release` label (`prometheusRule.labels: {release: <its release name>}`) or Prometheus won't load them.
- **Lists:** the new shrink guard is on by default; set `[filter] max_shrink_percent = 100` to turn it off.
- **Flow history** starts at the upgrade: minutes counted by 0.4 have no flow counts, and the card says so.

## Known issues

- **DNSSEC `validate` mode:** right after a start, an upstream that closes fresh DoT connections can make the first validations fail, so a signed name may get SERVFAIL until its keys are cached. Keep `permissive` or `off` for now; see ADR-098.
- `_dns.resolver.arpa` (encrypted-DNS discovery) is forwarded upstream instead of being answered locally.
