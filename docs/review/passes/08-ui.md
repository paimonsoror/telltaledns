# Pass 08: web UI

**Output:** `docs/review/v0.2.0/08-ui.md` (+ `patches/08-*`)

## Scope
The Svelte web UI embedded in the binary: dashboard, query log and Why?, devices and groups,
lists, upstreams, local names, cluster, alerts, analytics, settings, sign-in, agent
approvals.

- `ui/src/` (pages in `pages/`, shared components in `lib/components/`, the API client
  `lib/api.ts`, generated types `lib/api-types.ts`, help topics)
- `ui/tests/e2e/` (Playwright), `ui/package.json` (budgets and checks)
- How it's served: `crates/telltale-api/src/ui.rs`

## Read first
1. `spec/07-api-and-ui.md` (UI parts); ADR-030, ADR-036.
2. `ui/src/App.svelte` (routing) → `lib/api.ts` → two or three pages end to end (start with
   `Dashboard.svelte`, `Queries`/query log, `Groups.svelte`).

## Look for
- **Correctness against the API:** loading, empty, and error states; stale data after
  writes; pagination and cursors; time zones; numbers that could mislead (rates vs totals).
- **Security in the browser:** XSS through query names, device names, list contents, or
  error messages (anything rendered with `{@html}`); token handling; CSRF expectations
  matching the API.
- **Accessibility:** keyboard use, focus, labels, contrast in light and dark themes,
  screen-reader names (the Playwright tests use roles and labels; are they meaningful?).
- **Performance:** bundle size (budget 400 KiB gzipped), large tables (thousands of log
  rows), live views (SSE) and memory over long sessions on a phone.
- **Consistency:** wording and behaviour across pages; the guided "Simple/Advanced" model
  (ADR-036).
