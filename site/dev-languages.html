Write a language pack

A language pack is your translation of the web UI, kept in one file. On a TelltaleDNS you can sign in to, you can make it, check it and try it in your browser with no other tools. The project's checks tell you what to fix before anyone reads it. This page is the whole path, from the empty template to the pull request.

The user's view is in Language packs (for translators). The decisions are ADR-189 (languages in the web UI) and ADR-190 (testing a pack in the browser). The contributor guide for the repository tool is the Languages section of ui/README.md.

What a language pack is

The web UI is written in English, and English never waits for a translation. A language pack is a plain data file, <tag>.json, with your translation of the UI's texts. A text you have not translated, or one the check cannot accept, shows in English.

Inside, each part of the UI is a list of pairs: the English first, your translation second. A part (a context) is named after the page or component that shows it, such as cache.

{
  "cache": [
    ["Holds","Qa-holds-zeta"],
    ["Kept by <b>{who}</b>","Qa-kept <b>{who}</b>"],
    [["{n} answer","{n} answers"],{"other":"{n} qa-answers"}]
  ]
}

An excerpt of the made-up test language this page uses for every example. Its tag is qaa, one that the language-code standards reserve for private use, so the card refuses it as a language. Your pack uses your language's real tag. The English texts in the examples are the test fixture's, not the UI's.

A pack is data and is never run. A translation is shown only while it agrees with the English it replaces: the same placeholders, tags, web addresses and numbers. If not, the English shows.

The words used here:

  • Tag (a language tag): the short code for a language, such as de or pt-BR.
  • Pack (a language pack): your translation of the web UI, in one file named <tag>.json. The page also says "your file". A pack is in use while your browser is showing it.
  • Template: the empty pack for a tag: every English text and no translation.
  • Fingerprint: the first 12 characters of a pack's SHA-256 hash, which the banner shows to tell one pack from another.
  • Pull request: GitHub's way of proposing a change to the project.
  • Manifest: ui/src/locales/manifest.json, the list of languages with their owners and whether each is offered.

Where this stands. No language ships with TelltaleDNS yet, and Settings has no language setting yet (ADR-189 puts it under Settings, Account, shown only once a language is offered). What exists today: the card Test a language pack, the repository tool, and ?lang=en-XA, a pseudo-language for finding text that cannot be translated yet. A pack you try is yours alone, in your browser.

Get the template

Two ways give the same template. The card needs a browser and a TelltaleDNS you can sign in to, with any role: your own, or a test installation (Get started shows how to run one). The repository tool needs a checkout and Node.

With the card

  1. Sign in and switch to the Advanced view with the Simple | Advanced switch at the top of the page (in the menu on a phone).
  2. Open Settings, then the Account tab. Find Test a language pack and choose Open. In the Simple view the card shows only while a pack, or a notice about one, is in this browser.
  3. Under 1. Get the template, type your tag in Language tag (such as de, fr, pt-BR or zh-Hant). The line below says what the card understood, for example German (Deutsch): written left to right; saved as de.
  4. Choose Download the template (de.json) and Notes for translators (de-notes.txt).

The card's link How to translate TelltaleDNS brings you to this page.

With the repository tool

You need a checkout, and Node 24 (22.18 and later also work). Install the packages once, then ask for your tag:

cd ui
npm ci
node scripts/i18n.mjs sync de

It prints i18n sync: src/locales/de.json and writes that file. It is byte for byte what the card downloads for de from the same build.

Settle your tag with the card's tag line first.

  • The language's name comes from your browser and is only for display. It decides nothing.
  • The direction follows the script: right to left for Arabic, Hebrew, Thaana, Syriac, N'Ko, Adlam and Hanifi Rohingya. For those the card adds The layout isn't ready for right-to-left languages yet.
  • The plural forms are the categories zero, one, two, few, many and other that your language uses. They come from ui/src/locales/plurals.json, a table the project checks in, and never from your browser. ja has only other, de has one and other, ru has one, few, many and other, and ar has all six.

The notes for translators

<tag>-notes.txt is plain text to read beside the template. It holds a header (the language, its tag and direction, its plural forms, the web UI build and the date). Then come how to translate, how to send the file, and the terms kept as written everywhere. Last come the notes, for the texts that have any. This is the last section of the notes file for the test language:

Notes per context
[cache]
  "Choose email or ntfy"
    keep as written: email, ntfy
  "Holds"
    note: A cache entry count
    sensitive: give a back-translation in the pull request

The lines above it (the header, the steps and the terms) say the same for every language, except the language's name, tag, direction, plural forms, build and date. A note can also say the English's own note: …: that is the third item of a pair, described under Translate.

Translate

Write your translation in the second place of each pair. Everything else is the project's, and has to stay as it is.

What to keep exactly

  • Placeholders such as {kind}: gaps the UI fills with a name or a number. Move them where your sentence needs them, but never rename or drop one. Never type a number in a placeholder's place. In a limit such as {max}, the UI writes the number as your language writes it, and you choose the noun form that goes with it. Keep {max} in every form of the plural.
  • Markup tags such as <b>…</b>: keep them around the same words and translate the words inside.
  • Web addresses, paths, ports, settings and commands: https://example.com/docs, /etc/telltale/, mail.example:587, max_ttl, text in backticks. Add no address, port, path, =, $ or | that the English does not have: the check fails it.
  • Numbers: every number of the English stays, written in digits.
  • The words the notes file lists as "keep as written", the values people type (email above), and the terms kept everywhere, such as NXDOMAIN.
  • No invisible characters, no characters that change the direction of text, and no word that mixes Latin letters with Cyrillic or Greek ones that look alike.

An empty translation ("") means "not translated yet". The English shows and nothing is wrong. A plural is a pair of two English forms and your forms, one for each category of your language. A form other than other may leave out a placeholder such as {n} only where the form is used for exactly one number, as English "one file" is for 1. Many forms are used for more. French and Brazilian Portuguese one is 0 and 1. Russian one is 1, 21, 31, 101 and so on. Latvian zero is 0, 10 to 20, 30 and so on. Keep {n} in a form unless you know that it covers exactly one number in your language. The CLDR plural rules for your language list what each form covers. Keep {max} in every form. A pair can have a third item, ["English","translation","note"]: the English's own note, which tells two uses of the same English apart. Keep it as it is in the template.

A message the maintainers mark sensitive (a destructive confirmation or a security warning) needs more care. If your pull request changes one, add a back-translation: your translation written back into English in your own words. A reviewer who cannot read your language can then see the meaning.

Five examples

Each shows a pair in the test language, what the card says about it, and the fix.

  1. A changed placeholder. The English is Notify by {kind}. 
    ["Notify by {kind}","Qa-notify {type}"]
    The card says two things:
    • Keep {kind} exactly as it is: it is replaced by a value.
    • {type} isn't in the English: a translation keeps the placeholders the English has, and no others.
    The fix is ["Notify by {kind}","Qa-notify {kind}"].
  2. A translated web address. The English is Read https://example.com/docs first. 
    ["Read https://example.com/docs first.","Qa-read https://qa.example/docs."]
    The card says four things:
    • Keep the web address exactly as in the English: https://example.com/docs
    • This web address isn't in the English: https://qa.example/docs
    • Keep https://example.com/docs as written.
    • Remove https://qa.example/docs: a translation adds no address, port, path or setting.
    One mistake can show more than once. Fix it once and they all go.
  3. A plural with the language's forms. The test language has only other (its notes file says Plural forms of this language: other.). Copying English's two forms is wrong: 
    [["{n} answer","{n} answers"],{"one":"{n} qa-answer","other":"{n} qa-answers"}]
    The card says This language uses other; this entry has one, other. Fix: write exactly the forms the notes file lists. A language with one and other gets a template line like [["{n} agent change to review","{n} agent changes to review"],{"one":"","other":""}], and you fill both.
  4. A note and a sensitive message. In the notes above, Holds has a note and is sensitive. Translate it from the note, not from the English alone. If you change its translation, the pull request needs a back-translation. When the check can compare your file with the one before it, it reminds you: 
    REPORT sensitive src/locales/qaa.json: context "cache": a sensitive message changed: its pull request carries a back-translation
    "Holds"
  5. An empty translation. ["Holds",""] is not an error. The card lists it under Not translated and the English shows. Leave a pair empty rather than guess.

Check it

There are two checks and they apply the same rule. The card runs it in your browser. In the repository, npm run check:i18n (in ui/) runs it for every language file, and so does CI, the project's automatic check of every pull request. FAIL means the author of the file can fix it. REPORT means a person reads it. A missing translation is a report, never a failure.

On the card

  1. Under 2. Check your file, use the field Choose your file (or drop it on the button) and pick your pack.
  2. Read the summary, for example placeholder.json: 7 of 9 texts translated (78%). 1 text breaks a rule and shows in English. The count is of texts. The list below shows every finding, so one text can appear in it twice.
  3. Open the lists: Breaks a rule, shown in English (1), Not translated (1), Left over (0) and Worth a look (9). Each entry names the part of the UI and shows the English, with your text and what to do where a rule is broken. A list shows 200 entries at most.
  4. Coverage per context, lowest first shows which parts of the UI still need work. Before you send it: what only the check of the pull request can judge lists what the card cannot know.
  5. Fix the file and choose it again. Repeat until nothing is under Breaks a rule, shown in English.

Worth a look never drops a text. For a language written in Latin letters it also lists your own words as Worth a look: the translation adds Qa-holds-zeta. Skim it for something you meant to keep.

With the repository tool

node scripts/i18n.mjs check is what npm run check:i18n runs. It exits with 1 when a line starts with FAIL. node scripts/i18n.mjs report prints the same lines and always exits with 0. A new language prints a long list of missing texts at first. Your file needs a manifest entry before the check will read it (see Send it); without one it says FAIL stray. Lines that name src/locales/<tag>.json or src/locales/manifest.json are about your work. Lines about script-text or literal-text are for the developers. A trimmed example, for the first example above:

FAIL agreement src/locales/qaa.json: context "cache": placeholders: missing
    "Notify by {kind}"
    "Qa-notify {type}"
    "{kind}"
FAIL agreement src/locales/qaa.json: context "cache": placeholders: added at 10
    "Notify by {kind}"
    "Qa-notify {type}"
    "{type}"

    "labels: Lists"
    "cache: Notify by {kind}"
REPORT coverage src/locales/qaa.json: "qaa": 7 of 9 messages (77.7%); owners: example-owner

Each FAIL shows the English, your text and the token it is about. The tool lists a text that fails as missing too, because English shows in its place. The card lists it only under Breaks a rule, shown in English.

Where the card and the tool differ

  • Plural forms. A wrong set of forms in one pair drops that one text on the card, and the check goes on. The tool fails the whole file and prints nothing else about it until you fix that.
  • Pairs under ~leftover are listed on the card and not printed by the tool.
  • Coverage is per context on the card and one line for the language in the tool.
  • The sensitive and swap lines come only from the tool. It compares your file with the copy in the commit before yours: in CI, and on your computer once your repository has an earlier commit. A swap is a new translation equal to another message's old one. With no earlier commit the tool says sensitive and swap lines: not checked.
  • The file's exact form. The card says Not in the repository's exact form: "Download for a pull request" fixes that. The tool says FAIL canonical (another layout, such as Windows line ends) or FAIL malformed … an unexpected character at offset 0 for a byte-order mark. The card reads past a byte-order mark and still calls the file not exact.
  • Tags (above) and the manifest: only the tool reads manifest.json.

Try it

Seeing your translation in the real UI finds problems no check can: a label that is too long, or a sentence that reads wrongly.

  1. On the card, choose your file, ideally with nothing under Breaks a rule, shown in English (those texts show in English), then choose Use this pack….
  2. Read the confirmation, Use this language pack in this browser?, and choose Use it and reload. Cancel changes nothing.
  3. The page reloads in your language. An English banner stays at the top of every page: Test language pack: … (…, fingerprint …). Labels come from that file, not from TelltaleDNS. It has Details, a link to Settings, Account, and Remove.
  4. To try a new version of the file, choose Check a new version of the file on the card, and use it again.

How long it stays

  • Where: in this browser only, for this TelltaleDNS address, and for the user who loaded it. Another user of the same browser sees their usual language. Any signed-in user can try a pack: it changes nothing on the server.
  • Removed by the page at the next page load after an upgrade of the web UI. After an upgrade of the server, it goes at the first page you open once you are signed in. A rollback or a downgrade counts as an upgrade.
  • Also removed 7 days after you loaded it, or when the kept copy cannot be read.
  • Also removed when it could not be checked twice in a row. That is an error in the check itself, not a finding about your file.
  • Also removed when a page cannot be drawn with it (the page then loads once more without it).
  • Removed by you with Remove in the banner or Remove and reload on the card.
  • Paused on the sign-in, setup and two-factor screens, which stay in your usual language unless you choose Show the test pack on this page (one page load).
  • Signing out. After you sign out, after your session ends, or after a sign-out at a sign-in provider, the page the browser loads is in your usual language, with the pack paused. A sign-in provider is an outside service that signs you in, such as a company's single sign-on. The pack returns when you sign in again.
  • Back and the provider. A page you return to with Back reloads first. The sign-in page already on screen as the browser leaves for the provider may still show the pack. If the provider never replaces the page, it may show the pack until the next page load or sign-in.
  • Real English: put ?lang=en after the address and before any #, for one page load: https://dns.example/?lang=en#/settings. Any ?lang= pauses the pack for that load.

What to look at

  • Long text. Buttons, table headings and menus at a phone's width of about 360 px.
  • Counts. A page that shows 0, 1, 2, 5 or 21 of something: does each form read right?
  • Right to left. Not ready. The card says The layout isn't ready for right-to-left languages yet. for such a language, so judge the words, not the layout.
  • Text that is still English. Open the UI with ?lang=en-XA. The translation layer is the code that looks each text up in the language pack. Every text that goes through it shows with accented letters and a few dots at the end, about a third longer, so Holds {n} reads Ĥóļðš {n}···. A text in plain English is not on the layer yet, and a translation cannot reach it: tell the maintainers in an issue. Some English is plain on purpose, so leave it. That is the test pack's own banner, confirmation and buttons, what the server says (error details and alert text), the in-app help, and names and values.

A developer with a checkout has a second way. A language that is in the manifest is built into the UI with "offered": false. Then ?lang=<tag> shows it for one page load, though it is not offered. ui/README.md has the commands to run the UI from the repository.

Send it

A pull request for a new language carries two things: your pack, and the language's entry in the manifest. The check fails either one alone. Ask in an issue first (CONTRIBUTING.md says so). A pull request that updates a language already in the manifest changes only its pack.

  1. Be sure nothing is under Breaks a rule, shown in English.
  2. Choose Download for a pull request (de.json). It is your file in the exact form the project keeps, with the texts you have not translated added as empty pairs. Or use the file sync wrote. Do not edit it afterwards: an editor can add Windows line ends or a byte-order mark.
  3. Add the language's entry to ui/src/locales/manifest.json, or ask a maintainer to add it to your branch. Without its entry your pack fails the check (FAIL stray), and an entry without its pack fails it too. Keep this layout exactly, or the check says not in canonical form: 
    {
  "de": {
    "dir": "ltr",
    "offered": false,
    "owners": [
      "your-github-name"
    ],
    "since": "0.9.0"
  }
}
    owners are the GitHub names of the people who answer for the language, without the at-sign. dir is ltr or rtl, as the notes file says. offered stays false for a new language. since is a release version such as 0.9.0, which a maintainer settles. All four fields are required. The check reads the layout byte for byte. Use two spaces of indent, the keys of an entry in alphabetical order, one owner to a line, and the languages in alphabetical order.
  4. Open the pull request with ui/src/locales/<tag>.json and the manifest entry, and nothing else. If you do not use git, say so in your issue and ask a maintainer how to send the two files.
  5. In its description, say the language and that you read every text (a machine translation is a draft only). Add a back-translation of each sensitive message you changed.
  6. Wait for the checks and for the review of the language's owner.

Who checks what

  • The reviewers check structure and need not read the language. The pull request changes only that language's pack, with its manifest entry when the language is new. npm run check:i18n is green. Every sensitive and swap line in the job summary is explained. The language's owner has approved.
  • The language's owner checks the translation: that it is right, reads well and means what the English means. The checks cannot know that.

How a language is offered, and taken off

  • A new language starts with "offered": false. A maintainer sets it to true at release time. Only then does the web UI use it for people whose browser asks for it. The setting that lets a person choose a language is not built yet.
  • The 80% rule (ADR-189): if a language covers under 80% of the previous release's text at two releases in a row, it stops being offered until it catches up. It stays reachable with ?lang=. No release step applies this yet, and there is no language to judge.
  • Right to left is not offered before the layout is ready: the check fails offered: true for such a language.

Keep it alive

  • The owner. The person (or people) named in the manifest answer for the language's content and approve changes to its file. Maintainers review the structure.
  • When the English changes. Any change to a text's English loses its translation, except spacing and the form of quotes, dashes and ellipsis. Adding a full stop or changing a capital letter counts. The translation stays lost until the owner confirms the new text, and the English shows meanwhile. Run node scripts/i18n.mjs sync <tag>: it keeps your translations, adds new texts empty, and sets the old pairs aside under ~leftover, or deletes them with --prune. A maintainer keeps translations through an edit that does not change the meaning with carry.
  • The CI summary. It lists the sensitive and swap lines of your pull request. Explain each in the description.
  • The terms. Terms such as NXDOMAIN are kept as written everywhere: the list is ui/src/locales/glossary.json, and the notes file shows it. A term that is missing is a request to a maintainer.

Safety

  • A pack never runs code. It is data, read by a strict parser. The card shows its text as plain text, never as markup.
  • Nothing leaves your browser. The card fetches the template from your own TelltaleDNS. When you choose Use it and reload, it also asks that server for its build and for who is signed in. The pack itself is never sent.
  • A pack can still make a label lie. A button that deletes something could say "Cancel", and no structural check notices. Load only a pack you made, or one from someone you trust, and load other people's packs only on a test installation.
  • The safeguards: a confirmation before a pack is used, and a banner above every page with the pack's file name and fingerprint. A pack is paused for any other user and on the sign-in screens. ?lang=en shows real English, and a pack ends after 7 days or on any upgrade.
  • What the checks cannot know is meaning. That is why every language has a human owner, and why a sensitive message needs a back-translation.

Troubleshooting

My tag is refused

Find your tag in the table of tags. The card tells you what to add or change. A language of several scripts needs its script (zh-Hans, not zh). If sync wrote a file but the check refuses its tag, follow the card's rules: see the note under that table.

The card says my file is damaged

The card refuses a file whole, and keeps nothing, with a message that starts This file can't be used:. These are its messages, with their limits. The line and column in the messages are examples: the card gives your own.

  • This file can't be used: it is larger than 1 MiB. A language file is far smaller, so you may have chosen the wrong file.
  • This file can't be used: it isn't UTF-8 text. Save the file as UTF-8.
  • This file can't be used: it isn't valid JSON (line 1, column 12). A comma, bracket or quote is wrong at that place.
  • This file can't be used: the key "cache" appears twice (line 1, column 15); the second would hide the first. A part of the UI appears twice. Merge them.
  • This file can't be used: it is nested deeper than a language file. The file has more levels than a language file.
  • This file can't be used: it isn't a language file (each context holds a list of pairs). The top level must be an object whose values are lists of pairs.
  • This file can't be used: it has more than 600 contexts. A language file has at most 600 parts.
  • This file can't be used: it has more than 10,000 pairs. A language file has at most 10,000 pairs.
  • This file can't be used: "Bad Context" is not a context name. A part's name starts with a lower-case letter and has only letters and digits (64 characters at most), or is ~leftover.
  • This file can't be used: pair 1 of "cache" is not in the form of the template. A pair is ["English","translation"], with an optional third item that is a note. A plural pair has two English forms and an object of forms.
  • This file can't be used: pair 1 of "cache" has a text longer than 4,000 characters. Any one text is at most 4,000 characters.

My language's plural categories are refused

The card says This language uses other; this entry has one, other. (with your own forms). The categories come from the project's table, not from your browser or your own knowledge of the language, and a plural pair needs exactly those forms. The header of your notes file lists them. If you believe the table is wrong for your language, say so in an issue: a maintainer changes it, after a review of the diff. The tool fails the whole file for this, the card one text.

Something shows in English although I translated it

  • It is listed under Breaks a rule, shown in English or Left over. Fix it there.
  • The page is not on the translation layer yet. Check with ?lang=en-XA.
  • The banner says the pack is paused. See What the banner says below.
  • The English of that text changed after you made the template. Download the template again.

What the banner says

The dots stand for the file's name. The banner is always in English.

  • The test language pack … is paused on this page. Nobody is signed in on this page (the sign-in, setup and two-factor screens), or it is a wall display's own page. A wall display is a screen an admin sets up under Settings, Users, Wall displays. The page its link opens is paused, and so is every page once the screen is signed in. The Wall display button at the top of the UI is not one of these: it still shows the pack. Choose Show the test pack on this page to see the pack for one page load.
  • The test language pack … is paused: another user of this browser loaded it. The pack belongs to the user who loaded it. Choose Show the test pack on this page, or sign in as that user.
  • The test language pack … is paused for this page load: the address asks for a language. Take ?lang= out of the address.
  • The test language pack … could not be checked, so this page is in your usual language. Reload to try again. Choose Reload. The pack stays.
  • TelltaleDNS was updated: the test pack goes away when you reload. Reload, then download the template again and check your file. Translations whose English did not change still apply.
  • The test language pack … was removed: TelltaleDNS was updated. Download the template again and check your file: translations whose English didn't change still apply. Do as it says, then use the file again.
  • The test language pack … was removed: it was loaded 7 days ago. Use the file again.
  • The test language pack … was removed: the copy kept in this browser couldn't be read. Choose the file again.
  • The test language pack … was removed: it could not be checked twice in a row. Check the file again under Settings. The check itself could not run, twice: it was not a finding about your file. Check the file on the card again.
  • The test language pack … was removed: a page could not be drawn with it. The page loaded once more in your usual language. Check the file on the card. If a file that passes the check keeps doing this, tell the maintainers in an issue, and say which page it was.

The tool says FAIL about a file or a field I did not write

  • FAIL stray src/locales/<tag>.json: the language has no manifest entry. See Send it.
  • FAIL manifest src/locales/manifest.json: "<tag>": src/locales/<tag>.json is missing: the entry has no pack beside it.
  • FAIL canonical src/locales/manifest.json: the entry is not in the exact layout. The message offers sync, which only rewrites the language's file. Copy the layout above.
  • FAIL manifest … "owners" lists the GitHub logins: write the name with no at-sign.

The check refuses a time, a price or a number in words

These fail as an added address, port, path or setting:

  • a time (24:00), a ratio (16:9) or a date pattern (TT/MM/JJJJ);
  • three or more items joined by slashes (a/b/c);
  • a grouped number (1.000.000.000) or a price ($5).

A number written in words fails the number rule. If your language needs either, say so in the pull request. A maintainer may allow that message in ui/src/locales/notes.json: the tokens it may add (exemptAdded) or the number rule (exemptDigits), with a reason.
